# Mahvex Security Policy

**Last Updated: September 2026**

Security is an important part of the Mahvex platform.

We appreciate responsible security researchers and users who
help us identify and report potential security vulnerabilities.

## 1. Reporting a Vulnerability

If you discover a potential security vulnerability affecting
Mahvex, please report it privately.

**Security Email:**

mahvex.official@gmail.com

Please do not publicly disclose the vulnerability before the
Mahvex team has had a reasonable opportunity to investigate and,
where appropriate, address the issue.

## 2. What to Include

When reporting a vulnerability, please provide as much relevant
information as possible, including:

- A clear description of the vulnerability.
- The affected Mahvex service or feature.
- Steps required to reproduce the issue.
- The potential security impact.
- Relevant screenshots, logs, or proof-of-concept information,
  when appropriate.
- Any suggested mitigation or fix, if available.

Providing detailed information helps us investigate the issue more
efficiently.

## 3. Responsible Disclosure

We ask security researchers to:

- Avoid accessing or modifying data that does not belong to them.
- Avoid disrupting Mahvex services or users.
- Avoid deleting or modifying data.
- Avoid testing against other users.
- Avoid publicly disclosing the vulnerability before coordinating
  with the Mahvex team.

If testing is necessary, please limit it to the minimum activity
required to demonstrate the issue.

## 4. Security Reports

Security vulnerabilities should not be reported through public
GitHub Issues, Pull Requests, Discussions, or other public
channels.

Private reporting helps protect Mahvex users while an issue is
being investigated and addressed.

## 5. Response

Mahvex will review submitted security reports and may contact the
reporter for additional information.

Response and remediation times may vary depending on:

- Severity of the issue.
- Complexity of the vulnerability.
- Required engineering work.
- Potential impact on users and services.

## 6. Scope

This policy applies to security vulnerabilities affecting Mahvex
services and infrastructure that are operated or controlled by
Mahvex.

Third-party services linked to or integrated with Mahvex may have
their own security reporting procedures.

## 7. Good-Faith Research

Mahvex appreciates good-faith security research intended to
identify and responsibly report vulnerabilities.

Researchers should avoid actions that could harm users, expose
private information, disrupt services, or compromise systems.

## 8. Security Advisories

When appropriate, Mahvex may use GitHub Security Advisories or
other appropriate disclosure mechanisms to communicate confirmed
security vulnerabilities.

GitHub provides repository security advisories that allow
maintainers of public repositories to privately discuss and fix
vulnerabilities before publishing an advisory.
